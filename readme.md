# Money

**Money** — интеграционное решение для автоматизации учета личных финансов на базе **1С:Предприятие** и Python.

Проект объединяет учет финансовых операций в 1С с отдельным Python-сервисом, который автоматизирует обработку банковских выписок в PDF и получение детальной информации о чеках по QR-коду.

## Возможности

- загрузка банковских выписок в формате PDF;
- автоматическое извлечение транзакций из PDF;
- определение доходов, расходов и переводов;
- нормализация и очистка банковских данных;
- удаление дубликатов операций;
- автоматическая категоризация операций по настраиваемым правилам;
- определение магазина/контрагента из описания операции;
- преобразование банковской выписки в CSV;
- получение данных чека по QR-коду;
- получение состава товаров, цен, количества и сумм;
- автоматическое создание/поиск магазинов и номенклатуры поставщиков в 1С;
- сопоставление товаров чека с внутренней номенклатурой;
- заполнение статей расходов;
- формирование расходов по товарам;
- массовая загрузка данных чеков для документов «Расход»;
- контроль соответствия сумм между товарами и расходами;
- отчет по расходам со средними чеками.

## Архитектура

Проект состоит из двух основных компонентов.

### 1. Расширение 1С

Каталог:

```text
AccountingOfGoods/
```

Содержит расширение конфигурации 1С `Money`, реализующее пользовательскую и прикладную часть решения.

Расширение добавляет интеграцию с Python-сервисом и расширяет работу с:

- банковскими выписками;
- документами «Расход»;
- чеками;
- номенклатурой;
- номенклатурой поставщиков;
- магазинами/контрагентами;
- статьями расходов;
- кошельками и счетами.

### 2. Python-сервис

Каталог:

```text
app/
```

Python-сервис построен на FastAPI и отвечает за операции, которые удобно выполнять за пределами 1С:

- разбор PDF;
- извлечение банковских таблиц;
- очистку и нормализацию данных;
- категоризацию транзакций;
- интеграцию с внешним API проверки чеков.

Обмен между 1С и Python выполняется по HTTP с использованием JSON.

# Сценарий 1. Загрузка банковской выписки

Пользователь выбирает PDF-выписку в интерфейсе 1С.

Далее выполняется следующий процесс:

```text
PDF-выписка
    ↓
1С
    ↓
Base64
    ↓
Python API
    ↓
Camelot
    ↓
извлечение таблиц
    ↓
определение транзакций
    ↓
категоризация
    ↓
нормализация
    ↓
удаление дубликатов
    ↓
сортировка
    ↓
CSV
    ↓
1С
```

Python-сервис извлекает из операции:

- дату;
- время;
- банковскую категорию;
- сумму;
- остаток;
- описание.

После обработки формируется CSV со следующими колонками:

```text
date
time
category
income
expense
balance
shop
transaction_type
description
```

# Сценарий 2. Категоризация операций

Тип операции определяется на основании категории, описания и знака суммы.

Используются три основных типа:

```text
income
expense
transfer
```

Правила хранятся в отдельном файле:

```text
rules.json
```

Например:

```json
{
  "income_keywords": [
    "заработная плата",
    "аванс",
    "поступление",
    "возврат"
  ],
  "transfer_keywords": [
    "перевод с карты",
    "перевод на карту",
    "СБП между своими"
  ]
}
```

Также можно настроить соответствие банковских категорий категориям учета:

```json
{
  "category_mapping": {
    "Супермаркеты": "Продукты",
    "Рестораны и кафе": "Еда вне дома",
    "Автомобиль": "Транспорт",
    "Отдых и развлечения": "Досуг"
  }
}
```

Таким образом, правила предметной области отделены от основной логики приложения.

# Сценарий 3. Получение данных чека по QR-коду

Для документа «Расход» в 1С можно указать QR-код чека.

1С отправляет QR-код Python-сервису:

```http
POST /check/
```

Пример запроса:

```json
{
  "token": "API_TOKEN",
  "qrraw": "QR_DATA"
}
```

Python обращается к внешнему сервису проверки чеков и преобразует его ответ в унифицированную структуру.

Пример результата:

```json
{
  "shop": {
    "name": "Магазин",
    "legal_name": "ООО Ромашка"
  },
  "items": [
    {
      "name": "Молоко",
      "price": 100.00,
      "quantity": 1,
      "sum": 100.00
    }
  ],
  "total_sum": 100.00,
  "datetime": "2026-01-01T12:00:00"
}
```

# Интеграция чека с номенклатурой 1С

## Настройка правил
Файл rules.json содержит списки ключевых слов для определения доходов и переводов. Изменения вступают в силу после перезапуска сервера.

## Состав проекта

Проект объединяет Python-сервис, расширение 1С и полную базовую конфигурацию:

- `app/` — Python/FastAPI-сервис;
- `Extensions/BankOperationsUpload/` — расширение 1С;
- `BaseConfiguration/Money_2_0/` — основная конфигурация 1С «Деньги» версии `2.0.44.28`.

Расширение разрабатывается для указанной версии основной конфигурации. Подробности находятся в `docs/architecture.md`, `docs/base-configuration.md` и `docs/development.md`.
После получения данных чека расширение 1С выполняет дополнительную обработку.

Для каждого товара:

1. определяется магазин;
2. находится или создается номенклатура поставщика;
3. определяется внутренняя номенклатура;
4. определяется статья расходов;
5. заполняются количество, цена и сумма.

Схематично:

```text
Товар из чека
      ↓
Номенклатура поставщика
      ↓
Внутренняя номенклатура
      ↓
Статья расходов
```

Если магазин или номенклатура поставщика отсутствуют, расширение может создать соответствующие элементы автоматически.

# Формирование расходов

После загрузки товаров из чека их можно распределить по статьям расходов.

Например:

```text
Молоко        100 ₽ → Продукты
Хлеб           50 ₽ → Продукты
Шампунь       300 ₽ → Здоровье и красота
```

Система группирует товары:

```text
Продукты              150 ₽
Здоровье и красота    300 ₽
----------------------------
Итого                 450 ₽
```

Перед сохранением выполняется контроль:

```text
Сумма товаров = Сумма расходов
```

Если суммы не совпадают, операция блокируется.

# Массовая обработка чеков

В 1С предусмотрена обработка для массовой загрузки данных чеков.

Система может найти проведенные документы «Расход», для которых есть QR-код и данные чека еще не были загружены.

После обработки документ помечается соответствующим признаком.

Предусмотрена также обработка QR-кодов, которые были сохранены в комментарии операции.

### `parser.py`

Отвечает за извлечение таблиц и транзакций из банковского PDF.

Используется `Camelot`.

### `transactions.py`

Выполняет основную обработку транзакций:

- категоризация;
- разделение доходов и расходов;
- разбор описаний;
- нормализация;
- дедупликация;
- сортировка.

### `categorization.py`

Содержит правила определения типа операции и извлечения магазина/типа транзакции из описания.

### `rules.py`

Загружает правила из `rules.json`.

### `check_service.py`

Изолирует интеграцию с внешним API проверки чеков.

### `endpoints.py`

Предоставляет HTTP API для взаимодействия с 1С.

# Ограничения

Текущая реализация ориентирована на банковские PDF-выписки определенного табличного формата.

Python-парсер ожидает таблицы с пятью колонками и определяет транзакционные строки по наличию:

- даты;
- времени;
- денежной суммы.

Поэтому поддержка произвольных банковских форматов PDF не гарантируется.

Кроме того, интеграция с внешним API чеков зависит от доступности этого сервиса, его токена и установленных им ограничений.

# Назначение проекта

Money предназначен для автоматизации рутинных операций при ведении финансового учета:

```text
Банковская выписка
        ↓
Автоматическая обработка
        ↓
Категоризация операций
        ↓
Учет в 1С
        ↓
QR-код чека
        ↓
Получение состава покупки
        ↓
Номенклатура
        ↓
Статьи расходов
        ↓
Аналитика расходов
```

Главная идея проекта — **связать банковские операции, чеки и товарную детализацию с финансовым учетом в 1С, вынеся специализированную обработку PDF и внешних API в отдельный Python-сервис.**
